#### Integrations
##### Orange Cyberdefense Threat Intelligence (Datalake)
- Renamed commands to follow XSOAR naming conventions. Old names are kept as aliases for backward compatibility.
  - `submit_sightings` → `datalake-submit-sightings`
  - `bulk_search` → `datalake-bulk-search`
  - `import-indicators` → `datalake-import-indicators`
  - `hashkey` → `datalake-lookup-hashkey`
- `datalake-submit-sightings` (and deprecated `submit_sightings`): renamed argument `impersonateID` to `impersonate_id`, and `visibility` to `description_visibility` (clarifying that only the sighting description visibility is controlled, not the sighting itself). The old names are kept as aliases.
- Added a new indicator field (`datalaketags`) to store Datalake tags.
- Added a new integration parameter to control whether Datalake tags are imported as XSOAR tags, in addition to the beforementioned `datalaketags` field.
- Reputation commands now always return an indicator with an *Unknown* verdict for values not found in Datalake, instead of returning no indicator.
- Updated the Docker image to use Datalake Python SDK v3.0.1.
- Improved bulk search speed for multiple query hashes when fetching indicators or using `datalake-bulk-search` and `datalake-import-indicators` commands.
- Updated fetch indicator process to prevent premature timeouts, allowing up to 30 minutes execution.
- Improved exception handling and error messages, especially around unsupported indicator types.
- Other code optimizations.

> **Note for existing instances:** The new *Add Datalake tags to indicator tags* parameter defaults to `enabled` for fresh installations, but will not be automatically enabled on existing instances after the upgrade. To keep the previous behavior and continue importing indicator tags, please open the integration configuration and check the box manually.
